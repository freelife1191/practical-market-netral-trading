# 원문과 지식 검수

## 전체 단위 대응

목차와 본문 경계에서 실제 장/주제 단위를 확인한다. 자동 감지한 제목 개수는 장 수가 아니다. chapters 폴더, chNN 이름, PDF, 특정 장 수를 가정하지 않는다. 서문·부록 제외는 사유와 범위를 남긴다. 기존 자료 구조를 보존한다.

inventory에 안정적인 단위 ID, 원문 파일/위치, 대응 스킬 파일, mapped/missing/excluded 상태와 사유를 기록한다. expected_unit_ids는 실제 목차 검토에서 정한 목록이다. 같은 목록 두 개를 생성했다는 것만으로 완전성이 증명되지 않으므로 source-reviewer가 원문에서 직접 확인한다.

mapped는 대응 파일을 찾았다는 뜻이며 내용 전체의 반영을 증명하지 않는다. 원문의 핵심 요소를 대응 파일의 실제 문장과 각각 대조하고, 없는 요소는 누락으로 표시한다. 원문에만 있는 내용을 대응 파일에도 있는 것처럼 쓰지 않는다. 색인·깨진 링크 같은 패키지 검수 항목은 원문 단위와 구분해 기록한다.

링크 대상의 부재는 실제 목록·검색·명확한 파일 없음 오류 등으로 확인한다. 이름이나 링크 문자열만 보고 없다고 단정하지 않는다. 권한 오류와 파일 부재를 구분하고, 실제로 확인하지 못한 경로는 미확인으로 남긴다.

## 세부 내용의 충실도

장 제목이나 절별 대표 주장 하나만 확인해 세부 내용이 모두 반영됐다고 판단하지 않는다. 실제 목차와 본문에서 기법·하위 주제를 나누고, 판단을 바꾸는 적용 조건·예외·대조 사례·수치의 초기값과 단위를 찾아 대응 문장과 비교한다. 목차 단위 ID는 유지하고 필요한 만큼 claim을 분리한다. 아래 항목은 검토 기준이며 모든 책에 같은 열·개수를 강제하는 새 증거 스키마가 아니다.

| 확인할 요소 | 기록할 근거와 판단 |
|---|---|
| 기법·방법 | 원문 위치, 실제 반영 문장, 빠진 판단 단계 |
| 성립 조건·예외 | 필요한 상태·대상·시점, 조건의 결합(모두 충족인지 하나만 충족인지), 적용을 좁히는 조건, 미확인 입력 |
| 대조 사례 | 비슷한 기법의 차이, 적용되지 않는 맥락, 사례가 보여 주는 범위 |
| 수치·수식 | 초기값·반복 주기·최초 적용 시점·단위·기준(분모·적용 대상)·누적/도달 값과 검산 |
| 강도·순서 | 필수·권장·예시의 구분, 행동하는 시점과 순서 |
| 용어·귀속 | 원문 용법, 일반 정의와의 차이, 저자·번역자·편집자·새 제안의 구분 |

요약 문장이 원문과 비슷해 보여도 판단은 달라질 수 있다. 특히 조건의 결합(원문은 하나만 충족하면 되는데 모두 충족으로 쓴 경우), 강도(권장을 필수로 쓴 경우), 기준(원문이 밝히지 않은 비율의 분모를 정해 버린 경우), 시점(나중에 하라는 일을 미리 하라고 쓴 경우)이 바뀌기 쉽다. 이런 차이는 제목이나 문맥 대조로는 드러나지 않으므로 원문의 해당 문장과 직접 맞춰 본다.

감사에서 나눈 점검 항목 수를 책의 공식 원칙 개수로 표현하지 않는다. 모든 문장·게임 사례·도판을 복제하는 대신 새 판단 조건을 주는 누락을 보완한다. 원문에서 확인한 수치 방법은 구체적이라는 이유만으로 제거하지 않는다. 사례의 값과 방법의 적용 조건을 함께 남긴다.

두 설명이 충돌해 보이면 설계 수준·대상·시점·전제 조건을 먼저 비교한다. 다른 층위의 설명을 임의로 오류 처리하지 않으며, 실제 모순이면 양쪽 근거와 한계를 남긴다. 원문 용어가 일반 정의와 다르면 책의 용법을 보존하고 차이를 표시한다. 외부 정의가 필요할 때 공식 사전·원 논문 등 직접 근거를 확인하며, 책에 실렸다는 사실을 현대 연구의 재현성·현행 시장·실제 성과 검증으로 확대하지 않는다.

## 주장과 귀속

| origin | 의미 | 근거 |
|---|---|---|
| author | 책의 직접 설명 | 원문 파일·장/절/쪽 |
| synthesis | 여러 설명을 스킬용으로 합성 | 관련 원문 위치와 합성 표시 |
| validation-guidance | 시험에서 검증한 적용 지침 | 오류 ID·실행 기록·적용 범위 |
| proposal | 새 응용·프로젝트 제안 | 가상 입력·미정 선택 |

원칙·방법·조건·예외·범위·예시 수치와 핵심 도구를 대조한다. 요약에서 중요한 방법이 빠지거나 근거 없는 규칙이 생기면 위치·영향·수정 제안을 남긴다. 원문 전체 문장을 복제하지 않는다. 사례를 보편 규격으로 승격하지 않는다.

귀속 오류는 두 방향으로 생긴다. 스킬이 만든 정리·체크리스트·분기표를 저자의 말로 쓰는 경우가 있고, 반대로 저자가 실제로 쓴 절차를 스킬의 적용 양식이라고 낮춰 쓰는 경우도 있다. 둘 다 원문의 해당 위치를 직접 확인해 판정한다. 스킬 문장이나 검토자의 기억만으로 "원문에 없다"거나 "저자의 말이다"라고 단정하지 않는다.

원문 내부 모순은 양쪽 위치와 한계를 기록하고 한쪽을 임의 선택하지 않는다. 적용 정책은 선택지/결정 질문으로 분리한다. 확정 조건을 미정 응답·저장 기술과 함께 흐리지 않는다.

정책은 확정된 적용 범위대로 해석한다. 필요할 때 대상·효과와 가격·혜택, 콘텐츠 규칙과 저장·재개 방식을 나눠 확인한다. 한 축의 제한을 아직 미정인 다른 축까지 자동 확대하지 않는다. 실제로 있는 상태·데이터·동선과 새로 도입해야 할 기능을 구분하고, 입력이 없으면 미확인으로 남긴다.

## 시각·추출 범위

원본 SHA-256, 실제 추출 방식, 폴백, OCR/표/수식 누락 가능성을 기록한다. 기존 추출물은 원본과 추출 설정의 동일성이 확인될 때만 재사용한다. 사라진 임시 경로를 유효한 근거로 기록하지 않는다.

시각 후보는 중요한 주장에 쓰인 표/그림 → 텍스트와 충돌하는 수치/관계 → OCR/열 정렬이 의심되는 자료 순으로 고른다. 모든 후보의 선택/미선택 사유, 실제 점검 위치와 캡처/렌더 SHA를 남긴다. 관련 자료가 없으면 none-identified로 기록한다. 심각한 표본 오류는 관련 점검 범위를 넓히되 전수 검수처럼 보고하지 않는다.

PDF 인덱스와 인쇄 쪽수는 각각 원문에서 확인한다. 다른 책에 일정 오프셋을 재사용하지 않는다. 원문 전체·이미지 전체·비밀 데이터는 배포 자료에 포함하지 않는다.

## 문장 단위 위치

장·절 머리말에 범위만 있으면 답변이 "40–62쪽"처럼 절 전체 범위로 인용하거나 위치를 지어내기 쉽다. 판단을 바꾸는 저자의 주장·조건·수치·예외 문장부터 그 문장의 근거 위치를 붙인다. 위치 단위는 원문 형식에 맞춘다. 쪽 번호가 있으면 쪽을, 없으면 절·문단처럼 안정적인 위치를 쓴다.

인쇄 쪽수와 PDF 인덱스가 다르면 둘을 함께 적고, 원문의 쪽 표시(꼬리말 번호 등)로 쪽마다 대응표를 만든다. 장마다 오프셋이 달라질 수 있고 장 표지처럼 번호가 없는 쪽도 있다. 자료의 위치 쌍은 이 대응표로 모두 기계 대조한다.

skill-refinement에서 새로 붙이거나 바꾼 위치는 source-reviewer를 새 컨텍스트로 다시 불러, 원문의 해당 쪽과 표본으로 대조하게 한다. 전체 위치 수·기계 대조 수·표본 수·불일치와 처리는 `source-reviewer/location-sample.json`에 남기고, 메인은 대응표·기계 대조 결과와 함께 skill-refinement 증거의 `evidence_artifacts`로 결속한다. 보고에서 표본 대조를 전수 검수로 표현하지 않는다.

위치는 원문 근거라는 표시이므로, 위치를 붙인 문장은 원문이 실제로 말한 범위까지만 쓴다. 한 문장에 원문 근거와 스킬의 해석이 섞이면 두 문장으로 나누고, 해석 문장에는 스킬 정리임을 밝힌다. 같은 사례를 원문이 두 곳에서 다르게 설명하면 두 위치를 모두 남긴다.

## 지식과 탐색 보완

입증된 오류·핵심 누락만 수정한다. 장 파일이 이미 참조 자료이면 무조건 이동하지 않는다. 자료 선택이 어려우면 질문/목적 → 파일/절 → 예상 산출물의 색인을 보강한다. 기존 용어·패턴·판단표를 연결하고 같은 내용을 복제하지 않는다.

특정 기법·사례·수치 조회는 관련 상세 절에서 시작하고, 넓은 설계 맥락이 필요하면 장 자료를 보충하도록 안내한다. 사용자가 지정한 읽기 범위는 유지한다. 실제 읽은 파일과 원문 위치를 밝히며 색인의 짧은 설명만으로 상세 조건을 단정하지 않는다. 진입점의 중복 요약은 줄이되 조건·예외·사례·수치와 탐색 경로는 참조에 남긴다.

행·키·중복 범위 같은 도메인 지침은 해당 도메인에 유지한다. 이 범용 후속 스킬은 검증 기반 지침을 저자 원칙으로 잘못 귀속하지 않는 규칙만 갖는다.

대상 SKILL.md는 여러 호스트에서 그대로 불러와야 한다. 프런트매터 키와 Claude Code가 불러올 때 바꿔 쓰는 본문 표기(`$1`, `$ARGUMENTS`, `${CLAUDE_SKILL_DIR}`, `` !`명령` ``)는 [호스트 연동](host-adapters.md#claude-code-로드-증거와-격리)을 따르고, static-checks의 `claude-load-substitution` 경고가 나오면 freeze 전에 고친다. 금액처럼 `$`와 숫자가 붙는 원문 표기는 참조 파일로 옮기거나 "1,000달러"처럼 바꿔 쓴다. 참조 파일은 Read로 읽혀 치환되지 않는다.

## 답변 시 지침 점검

자료가 정확해도 답변하는 모델이 자료를 잘못 쓰면 결과가 틀린다. skill-refinement에서 대상 SKILL.md가 아래 지침을 답변 모델에게 알려 주는지 확인하고, 빠진 것만 그 스킬의 문체로 보탠다. 앞의 세 항목은 자료를 쓰는 방식에 관한 것이라 대부분의 책 스킬에 해당한다. 넷째처럼 책의 내용에 따라 달라지는 항목은 대상 책에 해당할 때만 보탠다. 이미 같은 뜻의 지침이 있으면 중복해 넣지 않는다. 지켜지는지는 [평가](evaluation.md)의 추적 점검으로 확인한다.

| 점검 | 지침이 필요한 이유 |
|---|---|
| 답변 근거는 스킬 폴더 자료다. 원문·추출물을 프로젝트에서 찾아 열지 않고, 확인할 원문 위치를 안내한다. 사용자가 원문 위치를 주며 대조를 요청할 때만 연다. | 설치한 환경에는 원문이 없는 것이 정상이다. 원문 탐색은 시간과 권한 확인이 들고 원문을 그대로 옮길 위험이 있다. 제작 프로젝트처럼 원문이 가까이 있으면 모델이 실제로 열려고 한다. |
| 고른 파일은 검색 결과 몇 줄이 아니라 파일 전체(긴 파일은 해당 절 전체)를 읽는다. | 조건의 단서와 예외가 문단 뒤쪽에 붙어 있는 경우가 많다. 검색 몇 줄만 읽으면 조건이 빠진다. |
| 위치가 붙은 서술은 책의 말로 옮기고 위치를 함께 적는다. 스킬 정리로 표시된 자료(정리·체크리스트·판단표·지침)와 자료 밖 일반 지식은 그렇다고 밝힌다. 어느 쪽인지 표시가 없으면 출처를 단정하지 않는다. | 답변에서 저자 원칙과 스킬의 정리가 섞이면 사용자가 근거의 무게를 판단할 수 없다. 위치가 일부만 붙은 자료에서 "위치 없음 = 스킬 정리"로 읽으면 저자 서술을 낮춰 쓰게 되므로, 스킬이 만든 자료에는 스킬 정리라는 표시를 함께 둔다. |
| 원문이 기준(분모·대상)을 밝히지 않은 수치는 사용자의 수치와 같은 척도로 맞대어 비교하지 않는다. | 기준이 다른 수치를 비교하면 원문에 없는 판정이 생긴다. |

자료 안의 "원본을 확인한다", "원문을 대조한다" 같은 문구는 답변 모델에게 원문을 열라는 지시로 읽힌다. 사용자에게 안내하려는 뜻이면 "확인할 원문 위치를 안내한다"처럼 행동의 주체를 바꾼다.
