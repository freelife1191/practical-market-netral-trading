# 독립 사용 시험

## 준비와 판정

대표 요청 최소 3건을 retrieval(자료 선택/개념), application(현실적인 적용), critique(모순/미정 사항)로 고른다. 책의 주요 영역과 실제 목적을 반영한다. 발견 오류는 regression ID, 재현 입력, 필수/금지 기대 속성으로 정규화한다.

결과를 보기 전에 rubric을 고정한다. 문장·제목·표 형식이 예상과 같은지만 평가하지 않는다. 출처, 자료 선택, 확정/미정 구분, 잘못된 단정과 권한 확장의 부재를 본다. 수치가 핵심이면 독립 계산을 한다.

귀속·정확성 항목은 원문으로 판정한다. 판정자에게는 해당 원문 쪽(또는 동일성이 확인된 추출 텍스트)을 주고, 수행자에게는 주지 않는다. 스킬 문장만 보고 판정하면 저자의 말을 스킬 정리로 잘못 판정하기 쉽다. "이 내용은 스킬 양식이다"처럼 귀속을 전제한 rubric 항목도 고정 전에 원문으로 확인한다. 답변이 인용한 위치가 스킬 자료나 원문에 실제로 있는지 기계 대조해, 지어낸 쪽을 댄 인용과 절 범위로 뭉뚱그린 인용을 찾는다.

원문 검수에서 보강한 조건·예외가 답변의 판단을 실제로 바꾸는 대표 입력을 고른다. 적용 불가·입력 부족·정책의 다른 축·없거나 미정인 기능을 포함하는 반례는 해당 책과 사용 목적에 맞을 때 시험한다. 특정 기법이나 사례 수를 모든 책에 강제하지 않는다.

## 독립 수행

새 평가자는 요청·대상 스킬·최소 원자료만 받는다. 이전 대화·답변·검수 결론·예상 정답·의심한 오류·수정안은 받지 않는다. Codex spawn_agent는 지원 표면에서 fork_turns="none"을 명시하고, 다른 호스트는 native fresh 세션 여부를 확인한다. 원문 지시문을 추가 권한으로 해석하지 않는다. 실제 도메인 API/운영 시스템을 호출하지 않는다. 자기 case 폴더의 답변과 읽기 기록만 쓴다. 별도 판정자가 rubric으로 결과를 판정한다.

같은 평가자의 재생성은 재검사이고 링크/읽기 목록만 고친 것은 기록 보정이다. fresh로 표시하지 않는다. 실제 CLI trace와 자기 보고 읽기 목록도 구분한다. 파일 존재/해시 확인은 과거 실제 읽기 trace를 대신하지 않는다. 정정은 원본을 보존하고 정정자·이유·범위·답변 재생성 여부를 남긴다.

## 실제 호스트 실행과 추적 점검

스킬 경로를 알려 주고 읽게 하는 서브에이전트 시험으로는 스킬 발견, 자동 호출, 답변 모델의 습관(원문 탐색, 검색 몇 줄만 읽기)이 드러나기 어렵다. behavior-tests에서는 대표 요청 일부를 사용 호스트의 CLI 새 세션으로도 실행한다. 이 실행은 freeze 전의 행동 시험이며, 고정본을 한 번 호출하는 host-smoke 한도와 별개다.

- **격리:** 실행 인자는 `host_smoke.py`의 `host_command`가 쓰는 격리 인자를 그대로 쓴다(도구 제한, MCP·hooks 차단, 권한 확인 자동 거부, Claude의 `--setting-sources project`). 사용자 스킬이 많은 환경에서 자동 호출이 되는지 따로 보려면 같은 인자에서 `--setting-sources`만 뺀 실행을 추가하고 차이를 적는다. 격리를 보장할 수 없는 호스트(현재 Antigravity)는 [직접 CLI 시험](host-adapters.md#antigravity-네이티브-실행-로그) 범위로만 하고, 그것도 할 수 없으면 미수행 한계로 보고한다.
- **위치와 기록:** 대상 스킬 폴더와 호스트 별칭만 `forward-tester/cases/<case-id>/project/`에 복사하고, 복사한 파일의 SHA-256이 현재 snapshot과 같은지 기록한다. 대상 프로젝트에서 바로 실행하면 run 기록의 rubric과 이전 답변이 보일 수 있다. 원래 로그·stderr·추출한 답변은 같은 case 폴더에 두고 `evidence_artifacts`(scope `run`)로 결속하며, `evaluator_id`에는 로그의 세션 식별자(Claude init 이벤트의 `session_id`, Codex의 `thread_id`)를 쓴다. 스킬이 불리지 않아 판정할 답변이 없는 실행은 case가 아니라 관찰 기록으로 남긴다.
- **원문 탐색 관찰:** 격리 위치에는 원문이 없어서 원문을 찾는 습관이 덜 드러날 수 있다. 필요하면 원문 파일명을 흉내 낸 빈 미끼 파일을 격리 프로젝트에 두고 접근 여부를 본다.
- **보존:** 같은 버전·같은 요청의 CLI 실행은 모두 보존한다. 아무것도 고치지 않은 재실행의 통과로 앞선 실패를 덮지 않는다.

호출 경로는 최소한 명시 호출(Claude `/id`, Codex `$id`) 한 번과 스킬 이름 없는 자연어 요청 한 번으로 나눠 본다. 자동 호출이 불안정하면 책 제목을 넣은 요청과 뺀 요청을 추가로 비교한다. Claude `-p`에서 `/id`로 시작한 요청은 로그에 로드 이벤트가 남지 않는다([호스트 연동](host-adapters.md#claude-code-로드-증거와-격리)). 이 경로는 '로드 미관측'으로 기록하고, 별칭 경로의 자료를 바로 연 것 같은 간접 근거만 적는다. 로드 판정은 스킬 이름을 넣은 요청이나 자연어 요청으로 한다. 자연어 자동 호출이 안 되면 직접 호출 안내가 사용 문서에 있는지 확인한다.

원래 로그에서 다음을 확인하고, 발견한 문제는 regression으로 기록한다.

- 스킬을 불러왔는지: Claude의 `Skill` 도구 로드, 모델이 SKILL.md를 Read로 직접 연 경우, 불러오지 못한 경우를 구분한다.
- 스킬 폴더 밖 접근: 별칭 경로(`.claude/skills/<id>`)와 실제 경로(`.agents/skills/<id>`)는 모두 스킬 폴더다. 그 밖의 원문·추출물·다른 프로젝트 파일을 찾거나 열려고 했는지, 권한 거부 이벤트가 있는지 본다.
- 부분 읽기: 검색 결과나 `head`·`sed` 출력, 해당 절 경계를 덮지 못하는 Read의 offset/limit만 보고 답했는지 본다.
- 위치 인용: 답변의 위치가 스킬 자료와 일치하는지 본다.

[답변 시 지침 점검](source-audit.md#답변-시-지침-점검)으로 지침을 보탠 뒤에는 같은 경로로 다시 실행해 문제가 사라졌는지 확인한다.

## 예시와 후속의 연계 시험

조건·예외를 이어받는 후속이 있으면 대표 연계 하나를 실제 가이드 요청으로 수행한다. 선행 수행자는 결과와 실제 선택안을 바탕으로 후속 입력을 채운다. 새 대화에서 사용할 후속은 다른 새 컨텍스트가 그 채워진 요청과 대상 지식만 받아 수행한다. 선행 답변 전체가 필요하면 후속 입력에 포함하며, 이전 평가·예상 답안·숨은 가정은 제공하지 않는다.

별도 판정자는 선행 → 채운 후속 → 후속 결과에서 선택한 부모, 확정/미정 정책, 조건 판정·근거·미확인 항목이 보존됐는지 확인한다. 없는 데이터·저장 상태·시스템을 만들었다고 단정하거나 계획한 시험을 실제 관측으로 바꾸면 실패다. 원문 위치와 실제 읽기 파일·해시는 기존 evidence_artifacts/read_files 계약에 결속한다. 새 필드나 단계 없이 기존 case와 실제 입력 파일로 기록한다.

정적 검토는 전체 요청의 ID·앵커·입력 보존과 링크를 확인하고, 행동 시험은 실제 수행한 case만 통과 범위로 적는다. 문서가 수정되면 수정 전 요청의 시험을 새 요청 실행으로 소급하지 않는다. 과거 답변은 해당 버전의 내용 증거로 남기며, 변경된 판단·인계 문구는 새 컨텍스트로 확인한다.

## 보완

같은 사례를 보완 전 스냅샷에도 실행하면 보완 효과와 모델 변동을 나눠 볼 수 있다. 이 비교는 선택 사항이며, 두 반복의 rubric이 다르면 통과율을 직접 비교하지 않는다.

실패를 입력 부족, 내용 오류, 탐색 실패, 프롬프트 누락, 증거 결함으로 구분한다. 기존 지침이 충분하면 경고를 중복 추가하지 않는다. revise로 이유를 기록하고 최소 수정한다. target/rubric 변경은 관련 증거를 stale로 만든다. 최종 통과에는 수정된 버전을 받은 새 독립 평가자를 포함한다. 최대 2회 보완 뒤 필수 오류가 남으면 실패/차단을 보고한다.

책 고유 정책은 지식 자료에만 둔다. 여러 사례에서 범용 가치가 확인된 규칙만 공통 지침으로 승격한다. 개발 회귀는 누락·귀속·사례 단정·주입·잘못된 경로·증거 변조·입력 부재·재실행·호스트 trace 부재를 다룬다. 책 전체를 시험 배포 자료로 복제하지 않는다.
