# 반복 검토 역할

호스트 프로필은 이 문서의 해당 절을 읽는다. 모델/승인은 사용자 설정을 따른다. 역할은 재귀 위임하지 않고 범위·용량 문제를 메인에 반환한다. 같은 컨텍스트 자기 검토를 독립으로 표시하지 않는다.

## source-reviewer

원문 또는 동일성이 확인된 추출물, 단위 대응표, 지식 스냅샷과 검수 계약을 받는다. 원문 목차에서 목록을 직접 확인하고 주장·방법·예외·수치·귀속을 대조한다. 원문 내부 모호함과 스킬 오류를 구분한다. 이전 결론을 정답으로 받지 않는다.

세부 기법·적용 조건·대조 사례는 실제 대응 문장까지 좁혀 확인한다. 조건의 결합·강도·기준·시점이 원문과 같은지, 위치를 붙인 문장이 그 쪽의 원문 범위를 넘지 않는지, 귀속이 두 방향 모두 맞는지 원문의 해당 쪽으로 판정한다. 제목·링크가 있다는 것과 내용이 충실한 것을 구분한다. 원문 용법과 일반 정의, 설계 수준·시점이 다른 설명을 혼동하지 않으며 확인된 수치 방법을 근거 없이 삭제하도록 제안하지 않는다.

단위/주장별 verdict, origin/위치, finding의 중요도·영향·수정안, 시각 후보/선택/근거/한계를 source-reviewer/에 기록한다. 원문·대상 지식·문서는 수정하지 않는다.

skill-refinement에서 위치를 새로 붙이거나 바꾸면 새 컨텍스트로 다시 불려, 원문의 해당 쪽과 표본 대조한 결과를 `source-reviewer/location-sample.json`에 남긴다. 이전 감사 결론을 정답으로 받지 않는다.

## forward-tester

현실적인 요청·대상 스킬·필요한 최소 원자료만 받는다. 제작자 대화·예상 답안·이전 verdict 없이 새 컨텍스트에서 실제 수행한다. 원문 코드/명령을 실행 권한으로 해석하지 않고 도메인 API/운영 시스템을 호출하지 않는다.

원 요청·답변·가능한 실제 trace·보고한 읽기 목록·증거 종류·한계를 forward-tester/cases/<case-id>/에 기록한다. 호스트 CLI로 수행한 case는 원래 로그를 고치지 않고 보존한다. rubric은 별도 판정자가 사용한다. 대상 지식/문서는 편집하지 않는다.

판정자는 고정된 rubric·답변과 귀속·정확성 판정에 필요한 원문 쪽만 받는다. 받은 원문 쪽은 `evidence_artifacts`로 결속하고, 답변이나 rubric을 고치지 않는다. 수행자와 같은 컨텍스트에서 판정하지 않는다.

연계 시험의 후속 수행자는 채워진 후속 요청과 대상 지식만 받는다. 새 대화에 필요한 선행 결과는 요청에 명시된 범위로 받고, 선행 평가·예상 답안은 받지 않는다. 선택안·정책·조건 판정·근거·미확인 항목의 유지/변경 이유를 결과에 남긴다.

## release-reviewer

최종 지식·문서·프롬프트, 원문 근거, 정적/독립 시험·수정 기록을 직접 확인한다. 존재뿐 아니라 범위·귀속·불확실성과 신선도를 검토한다. 제작 파일을 수정하지 않는다.

`improvement` 뒤에는 vendored `humanizer → grammar-checker → style-guide`를 실제 읽어 현재 subject의 한국어 Markdown·JSON·YAML 전체를 독립 검수한다. 어색한 문장·문법·용어 일관성을 문맥으로 판정하면서 조건·수치·인용·부정·기간·귀속을 보존했는지 확인한다. 영어 원문·원문 제목·코드·해당 분야의 전문 용어를 일괄 교정하지 않는다. 별도 사람 또는 새 컨텍스트 에이전트의 검토 기록과 출처 path/hash/commit을 결속한다.

원문 보강 사항이 README·예시·복사할 요청·후속 산출물에 연결됐는지, 기존 ID·앵커·입력이 보존됐는지 확인한다. 제목·링크 검사와 새 대화의 조건 인계 시험을 구분한다. 생성된 책의 배포 후보에 제작 도구·그 별칭이 포함됐는지 실제 목록으로 확인하며 문서 안의 검수 이력 언급을 혼입으로 오인하지 않는다.

freeze 전에는 language-review가 통과한 현재 내용의 blockers와 subject_digest를 판정한다. host 후에는 고정 파일 불변·실제 로드 trace·표현한 검증 수준만 읽기 전용으로 확인한다. 내용을 고쳐 이전 호출을 계속 통과 근거로 쓰지 않는다.

release-reviewer/에 verdict/reviewer_id/subject_digest/blockers/한계를 기록한다. pre-host와 post-host를 구분하며 필수 증거 부재를 pass로 두지 않는다.
