# 대상 지식 스킬 문서

## README와 가이드

단일 스킬 프로젝트는 루트 README와 docs가 정본이다. 여러 스킬/앱 저장소에서는 기존 README를 보존하고 사용 섹션·링크를 추가하며 docs/<skill-id>에 가이드를 둔다. 기존 파일을 템플릿으로 전부 덮어쓰지 않는다.

README는 설치 → 시작하기 → TOC → 간단 사용/프롬프트 → 전체 자료 구성 → 가이드 → 출처·한계를 담는다. 프로젝트 이름과 실제 호출 ID를 구분한다. URL을 모르면 공개 저장소를 추정하지 않고 로컬 전체 폴더 복사 예시를 쓴다. 프롬프트 설치와 CLI 설치를 모두 안내하고 기존 대상 보존 조건을 둔다. 변환기 설명을 완성된 지식 스킬의 사용자 문서에 섞지 않는다.

가이드는 색인·시작하기·호스트·작업 흐름·고급 활용·검수·문제 해결로 책임을 나눈다. README만 읽어도 기본 사용이 가능하며 상세는 명확한 링크로 연결한다. 빈 문서를 만들지 않는다.

문제 해결에는 자연어 요청으로 스킬이 자동 호출되지 않을 때의 호스트별 직접 호출 방법을 둔다. 원문과 대조하고 싶을 때 원문 위치와 확인할 쪽을 함께 주며 요청하는 방법도 둔다. 호스트 안내에는 지원하는 호출 경로(명시 호출/자연어)를 적는다. 이번 run의 실제 호출 버전·날짜·결과는 문서에 쓰지 않고 run 기록에만 둔다. 문서가 바뀌면 검증한 버전이 달라지기 때문이다. 이전 run의 확인 결과를 적을 때는 run ID와 버전을 함께 쓴다.

## 전체 단위의 고급 활용

모든 장/주제를 실제 자료 위치·활용 목적·관련 단위로 연결한다. 단위별로 유용한 상황, 읽을 자료, 서로 다른 목적의 고급 예시 2개, 결과를 이어 받는 후속 요청 1개를 작성한다. 각 예시에 입력·원하는 산출물·미정 사항·기대 속성·검토 기준을 붙인다.

공통 고급 예시 4개는 자료 선택, 같은 조건의 대안 비교, 변경 영향, 산출물의 일관성 검토다. 연계 시나리오 3개는 신규 적용, 기존 문제 개선, 변경 후 검증이다. 실제 책에 맞춰 구성하며 이 가이드의 절차를 저자의 공식 절차로 귀속하지 않는다.

가상 수치/명칭/정책은 가상 입력이다. A/B 후속 요청은 실제 선택한 결과에 이어 간다. 전체 프롬프트에 ID·파일/절 위치를 부여해 정적 검토 누락을 확인한다. 실제 장/예시 개수를 계산하고 특정 책의 숫자를 재사용하지 않는다.

## 보강한 조건을 예시와 후속으로 연결

지식·references의 보강 사항마다 README의 문제별 안내, 관련 예시의 입력·산출물·확인 기준, 후속 요청의 인계에 실제로 반영됐는지 대조한다. 원문 조건을 설명문에 덧붙이는 것만으로 끝내지 않고 복사할 요청 안에서 판단할 수 있게 한다. 이미 충분한 예시는 유지한다.

기존 요청 ID·앵커·순서·가상 입력·확정/미정 정책·숫자는 보존한다. 기존 장르·시나리오와 맞지 않는 조건은 원래 입력을 바꾸지 않고 별도 보완 예시와 필요한 후속으로 분리한다. 추가 개수는 누락된 맥락에 따라 정하며 특정 책의 최종 예시 수를 기본값으로 삼지 않는다.

| 위치 | 연결할 내용 |
|---|---|
| README·선택 표 | 현재 문제 → 확인할 조건·예외 → 목적이 보이는 직접 바로가기 |
| 선행 예시 | 조건의 성립·불성립·미확인·해당 없음, 원문·입력·관측 근거, 다음 확인 자료 |
| 후속 입력 | 실제 선택한 안·유지할 정책·앞선 결과, 조건 판정·예외·근거·미확인 항목 |
| 후속 산출물 | 이어받은 판정의 유지/변경과 이유, 변경 영향·새 반례·검증할 질문 |

위 네 상태는 적용 판단용이며 source-audit의 verdict나 실행 단계의 pass/fail/blocked를 바꾸는 값이 아니다. 해당하지 않는 조건은 짧게 이유를 적고 강제로 시스템·목표·정책을 추가하지 않는다.

후속 제목·부모 링크·복사할 요청은 실제 이어받을 선행 결과와 맞춘다. A 또는 B 어느 쪽을 받는지 불분명한 채 제목만 고치지 않는다. 같은 대화에서는 앞선 결과를 참조할 수 있지만 새 대화에는 판단에 필요한 결과·조건·근거를 직접 제공한다. 다음 형식은 필요한 인계 항목의 예시다.

```text
[대상 지식 스킬] 선택한 결과의 [검토할 부분]을 보완해줘.
선행 결과·선택안: [실제 결과와 선택 이유]
유지할 확정 조건 / 미정 사항: [정책과 아직 결정하지 않은 축]
이어받을 조건·예외: [판정 / 원문·입력·관측 근거 / 미확인 항목]
판정이 유지되거나 바뀌는 이유, 새 반례와 다음 확인 자료를 남겨줘.
```

일부 명령·원문 검수에 제작 도구나 로컬 원본이 필요하면 선택적인 제작 작업으로 설명한다. 일반 학습·사용 안내에서 제거된 도구가 설치돼 있다고 가정하지 않는다. [배포 분리](packaging.md)의 범위에 맞춰 문서의 호출 경로와 검토 기록 링크도 확인한다.

## 프롬프트 제목과 바로가기

각 예시와 후속 프롬프트에 목적이 드러나는 제목을 붙인다. 목차·장별 바로가기의 표시 텍스트는 해당 절의 실제 제목을 사용해, 클릭하기 전에 무엇을 할 수 있는지 알 수 있게 한다. A/B/C/D는 구분자로 덧붙일 수 있지만 `예시 A`, `후속 요청`, `이동`만 표시하며 제목을 생략하지 않는다.

긴 제목 여러 개는 글머리 목록이나 표로 배치한다. 한 줄에 구분점으로 몰아넣어 제목을 줄이지 않는다. 예를 들면 다음처럼 표시한다. 아래 제목과 앵커는 설명용이며 실제 문서에서는 해당 절에 맞춘다.

```markdown
- [A. 공유 재화로 도달 가능한 성장 경로 검증](#shared-resource-growth)
- [B. 고정 보상과 확률 보상의 목표 달성률 비교](#reward-comparison)
- [후속. 소비 우선순위를 바꾼 성장 경로 재검증](#growth-followup)
```

제목을 바꾸면 바로가기 표시 텍스트도 맞춘다. 앵커가 유효한지와 표시 제목이 목적지 제목에 맞는지는 따로 검토한다. 링크·앵커 자동 검사 통과만으로 표시 품질을 확인했다고 보고하지 않는다.

## 표현과 검토

TOC·비교표·구분선·강조·GFM NOTE/TIP/IMPORTANT/WARNING을 의미에 맞게 쓴다. 프롬프트 코드 블록과 터미널 명령을 구분한다. 전체 예시의 문맥·자료 경로·호스트 표기·귀속·미정 정책·기대 속성을 검토한다. QA 시나리오 작성과 실제 실행 결과를 구분한다. 정적 문서 검토를 행동 시험으로 보고하지 않는다.
